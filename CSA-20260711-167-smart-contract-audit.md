## Executive Summary
The audited Anchor on-chain program presents multiple critical vulnerabilities due to missing signer checks and unchecked arithmetic operations. An attacker could drain the vault by crafting malicious instructions that bypass authority verification or trigger integer overflow. The overall security posture is weak and requires immediate remediation before deployment.

## Key Findings
- Missing `#[account(signer)]` on the authority account in `withdraw_funds` allows anyone to transfer tokens from the vault.
- Unchecked addition in `update_rewards` can overflow, breaking reward distribution or enabling exploitation.
- Reinitialization attack possible because `user_stake` account lacks proper `#[account(init)]` and uses `init_if_needed` without validation, allowing overwriting state.

## 🔧 Remediation Plan

### V-01 — Missing Signer Check on Authority
**Severity:** CRITICAL | **Location:** `withdraw_funds() in lib.rs`

The function does not verify that the authority account has signed the transaction. The `authority` field lacks `#[account(signer)]`, allowing any caller to withdraw assets from the vault.

```rust
#[account(mut, signer)]
pub authority: Signer<'info>,
// or add has_one = authority constraint on vault
```

---

### V-02 — Unchecked Integer Overflow in Rewards Calculation
**Severity:** HIGH | **Location:** `update_rewards() in instructions.rs`

The line `user.accumulated = user.accumulated + amount;` uses plain Rust addition without overflow protection. An attacker supplying a large amount could overflow `accumulated`, corrupting state and potentially underflowing later subtractions.

```rust
user.accumulated = user.accumulated.checked_add(amount).ok_or(ErrorCode::Overflow)?;
```

---

### V-03 — Reinitialization Vulnerability via init_if_needed
**Severity:** HIGH | **Location:** `create_stake_account()`

The `#[account(init_if_needed)]` constraint doesn't check whether the account already exists, allowing an attacker to reinitialize the stake account with new data, resetting staked amounts and stealing rewards.

```rust
Replace init_if_needed with explicit init using seeds and a bump, or add a discriminator check to prevent reinitialization.
```

---

### V-04 — Business Logic: No Minimum Stake Check
**Severity:** MEDIUM | **Location:** `stake_tokens()`

The function allows staking 0 tokens, which can be used to create dust accounts, bloating the ledger and potentially enabling griefing attacks. Add a check that amount > 0.

```rust
require!(amount > 0, ErrorCode::ZeroAmountNotAllowed);
```
